Java 8 introduced the Stream API, a powerful feature for processing collections of data
in a functional, declarative way. Streams allow you to perform operations like filtering,
mapping, sorting, and reducing on data in a concise and efficient manner.
Below, I’ll explain the core concepts of Java 8 Streams, provide examples for each,
and break down how they work.

1. What is a Stream?
A Stream is a sequence of elements supporting sequential and parallel aggregate operations.
It’s not a data structure but a way to process data lazily, meaning computations are performed
only when needed. Streams are designed to work with collections, arrays, or other data sources.

Key Characteristics of Streams

Lazy Evaluation: Operations are not executed until a terminal operation is invoked.
Immutable: Streams don’t modify the original data source.
Single-use: A stream can be traversed only once; attempting to reuse it throws an exception.
Functional Style: Streams encourage functional programming with operations like map, filter, and reduce.


2. Stream Pipeline
A stream pipeline consists of three parts:

Source: Where the stream originates (e.g., a collection, array, or I/O channel).
Intermediate Operations: Operations that transform the stream (e.g., filter, map, sorted). These are lazy and return a new stream.
Terminal Operation: Produces a result or side-effect (e.g., collect, forEach, reduce). This triggers the processing of the stream.


3. Creating a Stream
Streams can be created from various sources:

Collections: List, Set, etc., using stream() or parallelStream().
Arrays: Using Arrays.stream().
Static Methods: Stream.of(), Stream.generate(), Stream.iterate().
Files: Using Files.lines() for reading file lines.
Other Sources: I/O channels, random number generators, etc.

stream() creates a sequential stream from a collection.
Arrays.stream() converts an array to a stream.
Stream.of() creates a stream from explicit values.
Stream.iterate() generates an infinite stream with a seed and function (limited to 5 elements here).
Stream.generate() produces an infinite stream based on a supplier (limited to 3 elements here).

4. Intermediate Operations
Intermediate operations transform a stream into another stream. They are lazy and only executed when a terminal operation is called.
Common Intermediate Operations

filter(Predicate<T>): Keeps elements that match a condition.
map(Function<T, R>): Transforms each element into another type or value.
flatMap(Function<T, Stream<R>>): Flattens nested streams into a single stream.
sorted(): Sorts the stream (natural order or custom comparator).
distinct(): Removes duplicates.
limit(long maxSize): Restricts the stream to the first n elements.
skip(long n): Skips the first n elements.

Explanation:

filter(name -> name.startsWith("A")): Keeps only "Alice" and "Alice".
map(String::toUpperCase): Converts "Alice" to "ALICE".
distinct(): Removes duplicate "ALICE".
sorted(): Not needed here since there’s only one element, but included for demonstration.
collect(Collectors.toList()): Terminal operation to collect results into a List.

5. Terminal Operations
Terminal operations produce a result or side-effect and trigger the stream pipeline’s execution. After a terminal operation, the stream is consumed and cannot be reused.
Common Terminal Operations

forEach(Consumer<T>): Performs an action for each element.
collect(Collector): Collects elements into a collection (e.g., List, Set, Map).
reduce(BinaryOperator<T>): Combines elements into a single result (e.g., sum, product).
count(): Returns the number of elements.
anyMatch(Predicate<T>): Checks if any element matches a condition.
allMatch(Predicate<T>): Checks if all elements match a condition.
noneMatch(Predicate<T>): Checks if no elements match a condition.
findFirst() / findAny(): Returns an Optional with the first/any element.
toArray(): Converts the stream to an array.

Explanation:

forEach: Prints each element.
collect: Gathers even numbers into a List.
reduce: Computes the sum of all numbers (1 + 2 + 3 + 4 + 5 = 15).
count: Counts numbers greater than 3 (4 and 5).
anyMatch: Checks if there’s at least one even number (true).
findFirst: Returns the first number greater than 3 (4).


6. Parallel Streams
Streams can be processed in parallel to leverage multi-core processors, improving performance for large datasets. Use parallelStream() or parallel() to enable parallel processing.

Explanation:

parallelStream() splits the stream into multiple threads.
The filter operation is executed concurrently, as shown by the thread names in the output.
Use parallel streams cautiously, as they can introduce overhead for small datasets or cause issues with non-thread-safe operations.


7. Collectors
The Collectors class provides utility methods to collect stream results into collections or other structures.
Common Collectors

toList(): Collects elements into a List.
toSet(): Collects elements into a Set.
toMap(Function, Function): Collects elements into a Map.
joining(): Concatenates strings with an optional delimiter.
groupingBy(Function): Groups elements by a key.
partitioningBy(Predicate): Partitions elements based on a condition.

Explanation:

toList(): Collects uppercase names into a List.
toSet(): Collects names into a Set, removing duplicates (none in this case).
toMap: Creates a Map with names as keys and their lengths as values.
joining: Concatenates names with a comma separator.
groupingBy: Groups names by their length.
partitioningBy: Splits names into two groups based on length > 4.


8. Optional
The Optional class is often used with streams to handle cases where a value may or may not be present, avoiding NullPointerException.

Explanation:

findFirst() returns an Optional<String> because no name may match the filter.
ifPresentOrElse handles both cases: when a value is present or absent.


9. Best Practices and Considerations

Use Parallel Streams Judiciously: They’re beneficial for large datasets but can add overhead for small ones.
Avoid Side Effects: Intermediate operations should be stateless and non-interfering.
Handle Exceptions: Use try-catch within lambda expressions if needed, as streams don’t handle exceptions directly.
Choose the Right Collector: Use toList(), toSet(), or toMap() based on your needs.
Short-Circuiting: Use limit, findFirst, or anyMatch to avoid unnecessary processing.

11. Primitive Streams
Java 8 provides specialized streams for primitives (IntStream, LongStream, DoubleStream) to avoid boxing/unboxing overhead.

Explanation:

IntStream.rangeClosed(1, 5) generates numbers 1 to 5.
sum() computes the sum directly.
filter and average work on primitive int values, avoiding boxing to Integer.


12. Debugging Streams
Use peek(Consumer<T>) to inspect elements during stream processing (useful for debugging).

Explanation:

peek prints elements at each stage (before filter and after filter) without modifying the stream.


13. Common Pitfalls

Reusing Streams: Streams can only be consumed once. Create a new stream for each operation.
Non-Thread-Safe Operations: Avoid modifying shared state in parallel streams.
Overusing Parallel Streams: They’re not always faster due to overhead.
Null Handling: Ensure streams don’t contain nulls, or use filter(Objects::nonNull).
